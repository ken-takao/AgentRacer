## 実装した実験経路

`DRIVING_MODE=telemetry` ではオペレーターが直接Decisionsを呼び、
各CUセッションには決まった1操作だけを渡す。新しい観測で再検証し、
古い判断・同じ設定の繰り返し・確定済み分岐・使用不可ジャンプを送信前に
除外する。成功確認はサーバーの新しい入力履歴と現在の設定の両方を使う。
操作中のタイムアウト・失敗を曖昧な成功として再実行しない。

ただしCUターンを毎回完了させる経路にも約9秒の待ち時間があり、
これを本番に切り替えても速くなるとは言えない。合法性検証は戦略上の
安全性を保証せず、送信後に古くなった判断も防ぎ切れない。

`RACE_PACE=sprint-2x` はこの実験モードで明示的に新規作成したv2だけに
適用される。移動速度を2倍、表示範囲を60→120、障害物の最低設置距離を
12→60にする。既存レース、車線移動、ジャンプ0.8秒、着地後2秒、スピン
1.2秒は維持する。オフラインの固定操作300シードでは中央値59.27秒、
p95 61.67秒（通常は116.14秒、118.54秒）だったが、AIの回避精度や
実レースの完走時間を示す結果ではない。

## 1分レースへ進むための選択肢

1. **CUを全操作に使い続ける場合**：APIの操作経路のさらなる短縮が必要。
   同一場面の画像/テキスト対照、遅延・追加障害物を含む回避試験、
   2セッションの実レースで衝突率と完走時間を確認してから速度を上げる。
2. **役割を変えられる場合**：Decisionsを戦略判断に使い、承認された操作を
   ゲーム側の決定的な実行器で適用する。予測到達時間と期限を持たせ、
   衝突直前の安全制御をサーバーで行う。これは全操作をCUで行う構成とは
   異なるため、今回その置き換えはしていない。
3. **時間を先に固定する場合**：現在の速度で60秒後の走行距離を競うルールに
   変更すれば、応答時間を悪化させず1レースを1分にできる。周回完走とは
   ルールが変わるため、今回自動では変更していない。

[Computer Use](https://developers.openai.com/api/docs/guides/agents-api/tools/computer-use)。

## 追試：車同士がすり抜けるルール

ユーザーの選択に基づき、新規レースは `carInteraction: "ghost"` とした。
車同士の接触判定、接触後4秒の減速、前走車への追従拘束をなくす。
障害物・バナナ・ジャンプ・速度・コースは維持する。既存の保存状態で
このフィールドがないものや `solid` を指定したものは従来ルールを保つ。
3D表示でも、追い越しで車が重なった際に接触防止の補間停止をしない。

判断側も車両回避を除去し、Decisionsの質問を3つから2つへ減らした。
テキスト方式では相手の位置を入力から除外する。画像方式では実際の
画面を使い、信頼されたサーバー状態に基づく指示で相手を無視する。
未評価の `rivalRisk` は `null` とする。稼働中の古いオペレーターへこの
判断変更を適用するには、レースを終えてから更新版を起動する必要がある。

事前固定した6場面を各2回、solid/ghostの順序を反転して計24回呼び出した。
同一場面のテキスト方式同士で、モデル・操作候補をそろえた比較である。

| 指標 | solid | ghost |
| --- | ---: | ---: |
| 許容行動に合格 | 8/12 | 12/12 |
| 平均応答時間 | 315.7ms | 332.6ms |
| 中央値 | 280ms | 273.5ms |
| 平均リクエストサイズ | 5,974 bytes | 3,969 bytes |

APIエラー0件、追加試行・期待値変更なし。入力は約34%小さくなったが、
速度改善は確認できなかった。ghostの平均には851msの1件が影響している。
この小標本で精度一般を保証したり、画像方式や2台の実走結果へ外挿しない。
詳細はGit対象外の `outputs/ghost/paired-results.json` と固定ケースに保存。

同じ操作を与えた物理シミュレーションでは、接触のない300シードは両方とも
中央値116.14秒で変化なし。側面接触が1回ある例は113.51→111.11秒で
2.4秒短縮。遅い前走車に同一車線で追従し続ける極端な例は、180秒制限終了
から80秒完走になった。これは車両接触による損失の除去を示すもので、
Computer Useの応答時間短縮や、1分完走の達成を意味しない。

## ジャンプ判断の調整

従来の指示は空き車線を優先し、ghostでは全車線が塞がると無条件に減速を
選ばせていた。画像用の一部に、ジャンプ可否を参加用READYから判断させる
誤記もあった。画像／テキスト・ghost／solid共通の指示に整理し、使用可能で
到達時刻が合うジャンプは、別車線が空いていても積極的に検討させる。
「今すぐ1回押す」操作であり予約ではないこと、遠い障害物に早過ぎる
ジャンプをしないことを明記した。物理・滞空時間・操作経路は変更していない。

調整中の失敗も含め、3段階で計44回の実Decisions呼び出しを記録した。
最初の強い優先指示は遠い障害物でも飛び、制約を先頭に置いた次の候補は
再びジャンプしなかった。最終候補は既存の近距離3ケースで0/3から3/3へ、
調整に使っていない近距離2ケースでも2/2でジャンプを選んだ。最終16ケース
では遠距離・使用不可の場面でジャンプを選ばず、APIエラーはなかった。

ただし許容操作全体は既存9/12、新規3/4。障害物がある別車線への移動や、
全車線閉塞・クールダウン中に塞がった車線を選ぶ問題は残る。
これはテキスト状況入力での選好比較で、画像認識や実走の回避率の改善を
示さない。近距離ケースは撮影時点で到達まで0.33〜0.56秒しかなく、実際の
Computer Useでは操作が衝突後に届く可能性がある。ジャンプを増やすことと
飛び越し成功率を上げることは別の検証が必要で、1分レースの根拠にはしない。
