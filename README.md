# Agent Car Game — Agent Grand Prix

2つの独立した Agents API Computer Use セッションが、画面のボタンを操作して競うリアルタイムレースです。ゲームはAIの思考中も止まりません。

## セットアップ

Node.js 22.13以降を使用します。このリポジトリにはAPIキー、管理キー、実行ログ、既存サイトのデプロイIDを含めていません。

```sh
npm ci
cp .env.example .env.local
cp .dev.vars.example .dev.vars
```

ローカルの設定ファイルに次の値を入力します。テンプレートの値は空です。

| ファイル | 変数 | 用途 |
| --- | --- | --- |
| `.env.local` | `OPENAI_API_KEY` | Agents APIにアクセスするキー |
| `.dev.vars` | `RACE_ADMIN_KEY` | 対戦作成・画像転送用の管理キー。公開ゲーム側にも同じ値を設定 |
| `.dev.vars` | `GAME_ORIGIN` | 自分がデプロイしたゲームのHTTPSオリジン |

これらの変数は環境変数でも設定できます。実際の設定ファイルはGitの追跡対象外です。

ゲームを公開してから、ローカルでオペレーターを起動します。

```sh
npm run operator
```

http://127.0.0.1:4180/ を開いて「2つのエージェントを起動」を押します。新しい観戦タブが開きます（開かない場合は「このレースを観戦する」）。実行にはOpenAI APIの利用料金が発生します。

公開ゲームはSites向けのVinext / Cloudflare Workers構成で、D1とR2を使用します。`.openai/hosting.json` にはストレージの宣言だけを保持しています。新しいSitesプロジェクトを登録してから、そのIDを設定し、Sitesのsource/build/packageワークフローで公開します。既存デモのデプロイ先へ自動接続する設定はありません。

`npm run dev` でフロントエンドをローカル確認できます。ただし、OpenAI側のクラウドブラウザーはこのPCのlocalhostへ接続できないため、AI対戦には公開された `GAME_ORIGIN` が必要です。

Roadsterの表示確認だけなら、開発サーバーを起動して `http://127.0.0.1:5173/preview/roadster` を開きます。赤・青のGLBが動くプレビューで、レースの作成やD1の準備は不要です。トップページの観戦リンクはレースが作成されたときだけ表示されます。

元の10台サーキット試作は `public/roadster-circuit/` に、実行に必要な車体と13種類の小物とともに保存しています。開発サーバー上では `http://127.0.0.1:5173/roadster-circuit/race.html` で確認できます。コースは `race.html` のThree.jsコードが生成しており、コース単体のGLBはありません。この試作はAgent Grand Prixのレース処理とは独立しています。

## 再対戦・リセット

終了・停止後は「新しいレースを開始」で、別の試合と2つの新しいセッションを作成できます。「表示をリセット」は操作画面だけを待機状態へ戻し、新しいAPIセッションを起動しません。実行中は停止と終了処理の完了を待ってください。終了処理が失敗した場合は「終了処理を再試行してリセット」で先に旧セッションを片付けます。

終了した公開観戦ページには「もう一度レースする」が表示され、主催者のMacの操作画面を開けます。新しい試合ができると「次のレースを観戦する」も表示されます。過去の結果ページは残ります。

## ゲーム

両車がREADYになると5秒後にスタート。左・中央・右の3車線と、SLOW・CRUISE・TURBOを選びます。選んだ操作は次の入力まで維持されます。障害物への接触で4秒間減速。先に200ユニットを走った車が勝ち、最大180秒で終了します。

中央のコースはサーバー時計から連続描画。2つのAI視点はComputer Useが取得した最新スクリーンショットで、動画ではありません。実APIの応答時間は変動します。

## 観戦画面の準備表示と音楽

観戦画面は、チームが追加した赤・青のRoadster GLBモデルを使う3Dサーキットです。車の位置・レーン・速度・障害物は既存のレース状態から描画します。3D側に独立した勝敗判定や操作処理はなく、Computer Useのエージェントは従来の2D操作画面を使います。観戦カメラは標準で自動モードになり、走行中は約7秒ごとに全体・追従・横からのショット・接戦の2台表示を切り替えます。視点は滑らかに移動し、手動カメラへの切り替えもできます。画面の動きを減らすOS設定では自動カメラを固定します。3D表示に対応しない環境では2Dに切り替えます。`/preview/roadster` では実際の対戦とは別のデモ走行を確認できます。

AIの準備中は55秒を目安にタイムゲージと各ドライバーの接続・READY状況を表示します。55秒を超えた場合は「もう少し時間がかかっています」と表示します。実際のスタートは両AIのREADY後の5秒カウントダウンで決まります。

走行中は `public/audio/turbo-battle-final-lap.mp3` をループ再生し、終了・中止で停止します。ブラウザーの自動再生制限がある場合は観戦画面のBGMボタンを押してください。音量調整とミュートができます。添付された音源を収録しています。

## 構成

- `lib/race-engine.ts`: 時計に基づく決定的なレース計算
- `app/api/races/`: D1による共有状態とプレイヤー別操作権限、R2による画像保持
- `app/race-ui.tsx`: 観戦画面とドライバー画面
- `public/models/tesla-roadster/`: Tesla Roadsterの10色のGLBと色一覧。コースでは赤・青を表示し、WebGLを使えない環境ではSVGの車を表示
- `operator/`: API起動・2本のイベント購読・画像転送・終了時削除

公開ゲームはOpenAI APIキーを保持しません。課金を伴う起動・停止はループバック限定のローカルオペレーターで行います。プレイヤーURLのフラグメントは試合と車両限定の操作キーで、30分後に期限切れになります。観戦画面は公開です。

エージェントには通常の画面操作だけを指示し、DOM・コード・直接ゲームAPIでの操作を禁止しています。APIには画像認識だけを強制するモードはないため、この制約はモデルへの指示です。

## 検証

```sh
npm test
npx tsc --noEmit
npm run build
```

物理テストではポーリング間隔が異なっても結果が一致すること、衝突・操作・同時到着・停止を検証。オペレーターのテストはモックAPIで行い、実際のAI運転とは区別しています。実走の証跡はプロジェクト内の `work/race-live-check.json` に保存され、Gitから除外されます。

公開はSitesのsource/build/packageワークフローを使用。D1スキーマは `drizzle/` のマイグレーションで管理します。
